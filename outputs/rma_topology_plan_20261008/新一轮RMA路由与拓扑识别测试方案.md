# 新一轮 RMA 路由与拓扑识别测试方案

日期：2026-10-08。状态：方案设计完成，尚未在计算节点执行。

范围：当前 SW39000 环境中，一个 CG 内 64 个 CPE 的 RMA 通信。先在一个 CG 建立证据，再在其他 CG、节点复核适用范围。

## 1. 本轮要交付什么

本轮采用“硬件事件观测为主、通信干扰为复核”的方法。目标是把实际通信时经过的可见部件记录下来，而不再主要依靠 RTT 增量拟合 XY/YX 重叠段数。

交付四项成果：

1. **编号对应表**：运行时 CPE 编号、行列、硬件簇编号、几何块编号、PMU 数组下标之间的对应关系。
2. **RMA 可见逻辑连接图**：观测到的簇间连接、方向及事件通道；每条连接都能追溯到原始计数记录。
3. **源簇到目标簇的路径记录**：16×15 个有向簇对，分别记录 PUT 请求/数据与完成相关流量；GET 单独验证。
4. **资源共享与负载行为**：哪些通信共用可见资源，哪些端点或方向出现容量约束，负载变化时端口使用是否改变。

“完整物理布线”“隐藏虚拟通道数量”“每个数据包的逐跳时序”不能由普通聚合计数器自动保证。若计数器只能确定多个等价路径，输出候选集合与缺失观测，不画一条未经确认的唯一线路。未观测到流量的连接不等于硬件不存在该连接。

## 3. 为什么原有干扰实验不够

已测到固定探针0→54在不同背景下明显变慢。例如1 KiB请求、8 B回信时，背景CPE 2→4对应约+34.96%，CPE 4→6对应约+3.54%。当前候选模型给这两个配置相同的特征，预测却需要不同结果。

新增跨行跨列背景已把14列设计矩阵提高到秩14，解决了参数重合；但是留出配置的预测误差仍高于常数加消息大小基线。由此不能选定XY或YX，也不能排除真实硬件采用某种XY/YX机制但当前代价模型遗漏关键因素。

还存在以下混合：

- 完整RTT同时包含去程、回程、端点响应、检查与等待。
- 相同4 KiB/W=4不保证实际背景注入速率相同。
- 旧快内核与补充内核的软件循环成本不同，绝对周期不能直接拼接。
- 单纯共边数量没有保留具体端口、位置、通道和仲裁信息。

本轮先观察单流引起的端口事件，再解释干扰，不继续用一个14项线性公式承担全部结构识别任务。

## 5. P0：先确认工具能用，不直接提交大扫描

### 5.1 核查项目

- 目标CPU/节点/CG、SDK版本、swgcc版本、运行时库和swperf库版本及哈希。
- 实际swperf.h中函数声明与手册一致；所选事件确有可链接符号。
- 当前作业是否允许访问计数器，计数器是否被系统性能采集器或其他作业复用。
- 第6章接口的实际数组长度和作用域；第5章的64核数组与第6章的16簇数组不得混用。
- CRTS/athread编号接口的实际定义；不根据相似名称自行猜测替代接口。
- 编译后代码和栈的位置。编程指南指出从核栈默认可位于主存，运行时有设置LDM栈的方式；应核对本站加载器用法、实际栈地址和LDM余量，不能把文档中的-b直接当成bsub参数。

随方案提供 collect_swperf_capabilities.sh，用于在登录节点收集头文件声明和库信息。它不提交作业，也不执行目标架构二进制。正式计数程序需要据收集到的实际SDK确认后实现。

## 6. P1：证明计数器确实“看见了RMA”

### 6.1 工作负载

依次运行：空内核、等循环长度的纯LDM计算、DMA-only、RMA PUT、RMA GET。DMA-only仅用于识别事件归属，正式RMA路径运行中不混入业务DMA。

RMA初选CPE核对：0→1、1→2、0→8、8→16、18→20、18→34、0→54、54→0。先用64 B、4 KiB；N=256、1024、4096；W=1；再加N=0的初始化/回收控制。拓扑阶段采用低注入速率：根据实测完成时间设置足够发送间隔，检查减半速率后端口签名是否稳定。

空控制与RMA控制应有相同配置加载、内核启动、结果回收结构。纯LDM控制用于发现循环、栈或检查代码是否额外引入主存访问；不能认为所有非RMA成本都与N无关。

### 6.2 采集时序

```text
主核：初始化已选事件 → 读before[16]
从核：加载固定配置 → 初始化LDM → 发N次RMA → 等待收发完成 → 回收固定大小结果
主核：join后读after[16] → 保存原始差值
```

主核在通信已结束后读计数，避免连续读计数器干扰正在测的网络。前后快照不要求不同CPE时钟同步。

该窗口仍包含启动、DMA配置、结果回收和必要同步，因此不能直接把after-before全算成RMA。对每个事件/数组项/消息大小拟合：

`count(N) = fixed_cost + N × per_operation_count`

保留原始计数、N=0控制及残差。用N增加时的增量识别与RMA数量一起增长的事件；固定控制成本由截距描述。若纯LDM控制的相关网络事件随N增长，先修正栈/内存位置等混入因素。

### 6.3 预设质控门槛

以下是实验质控值，不是硬件定律；只允许在开发阶段依据空控制噪声修订，进入独立验证前冻结。

- 每个事件至少采集100个空控制窗口，覆盖所用采集时长；有效计数增量超过空控制99%经验范围，并随N可重复增长。该阈值只用于初筛，最终判定还要求重复性和流量约束一致，不能凭一次越界认定连接存在。
- 对已确认计数单位的事件，N缩放的主要非零分量归一化残差目标不超过5%；小计数采用绝对噪声界限。
- 目标RMA数量、最终完成数量、数据检查一致；无超时、溢出或背景上限命中。
- 读计数器开/关的性能对照中，扰动目标小于2%；超过时把计数与纯计时拆成匹配运行，分别报告。
- 计数器宽度、溢出规则不明时缩短采集窗口，不能默认64位存储等于64位硬件计数器。

若某事件对DMA有响应、对已确认完成的RMA无响应，应标记“不适合作为该RMA路径的观测”，不能据零值判定不存在通信。

## 7. P2：把16项计数结果映射到实际小簇

所有64个CPE在计时外输出运行时tid、rid、cid、cgn、spcn、spc_tid。几何块编号仍另外计算为4×floor(r/2)+floor(c/2)，并与硬件编号逐项比较。

随后64个CPE逐个作为发送端，在其报告的簇内选择另一个核，发固定数量PUT；通过已校准的TBOX描述符/传输量定位计数数组中响应的位置。N先用256、1024。再用跨簇流量区分发起侧、接收侧事件。

生成：

```text
CPE → 运行时行列 → 硬件簇号 → 几何块号 → PMU下标 → 证据case_id
```

同簇四核的计数归属应一致或形成可解释的子结构。若不一致，保留实际结果，不能为了得到16个2×2块而强制归类。

图纸的上下/左右显示方向与坐标增加方向也要记录；通过相邻源目标实验校准E/W/N/S事件，不能只看手册插图朝向。

## 8. P3：每次只发一条流，恢复可见连接和路径

### 8.1 先看48个相邻方向，再覆盖全部240个簇对

在已验证的16簇映射上，各簇先选同一成员位置作为代表核。16簇所有有向不同簇对共240个，其中几何横纵相邻有向组合48个。

先运行48个相邻组合，观察端口映射和中间簇是否有事件；随后补齐其余192个组合。不能因为几何相邻就预设它们使用一条直接物理链路。

默认PUT、64 B和4 KiB、N=256/1024/4096、低速W=1。每次仅一个源发送，目标只等待远端完成，不逐条发送应用层回信。最后统一排空、校验。

去掉应用层回信仍然可能存在硬件回答字、确认、请求或控制流量；这些必须通过事件类别和大小扫描识别，不能称为“完全没有反向流量”。

### 8.2 用端口事件约束路径，而不是把所有亮点连起来

对于每个有向簇对，保存全部有效事件的16项归一化计数，形成端口使用签名。先保留原始事件名，再使用校准后的端口/方向/通道别名。

恢复步骤：

1. 用多个单流实验的签名匹配可能相连的输出/输入端口，并检查包/FLIT计数的对应关系。
2. 在已确认的事件单位下，检查中间部件的流量守恒；允许文档/校准解释的分包、转换和控制流量。
3. 用源、目标位置以及端口配对约束，枚举能解释观测的有向通路。
4. 仅在通路唯一、连通且无未解释分支时输出唯一的可见路径；否则输出多条候选或聚合边使用集合。
5. 在全体源目标组合中检查同一连接解释是否一致，保留与文档图不一致的证据。

单次多个端口同时增加不能证明它们相邻，更不能确定事件发生先后。普通聚合计数器若只能看到多条路径混合，仍需要更细事件、流过滤或硬件trace才能确定逐包顺序。

### 8.3 请求、数据和回答流量分别处理

在8个代表簇对上追加8、64、128、256、1024、4096 B大小扫描。选择簇对0↔15、3↔12、5↔10、6↔9，覆盖正反方向、角落和内部转弯。

固定N改变消息大小，观察哪些事件随有效载荷增加、哪些主要随操作次数变化。包头也可能随分包数量增长，不能把大消息减小消息的全部差值都称为纯数据。

再比较同一有效载荷方向：

- PUT：源簇s主动把数据写到目标簇d。
- GET：目标簇d主动从源簇s读取数据，数据仍从s到d，但请求发起方向改变。

由此识别请求与数据返回是否使用不同可见通道。PUT结论不能自动推广为GET、广播或其他操作的结论。

## 9. P4：判断路由规则，并排除端点造成的假象

### 9.1 候选规则

根据P3实际观察到的连接图比较XY、YX、与源目标/通道相关的固定路由，以及负载相关的多路径解释。文档中的CMesh作为待核对的结构依据，不强制把网络简化为单一4×4同质网格。

对240个簇对按几何类型划分：同一行/同一列96个，行列均不同144个。后者是区分转弯次序的重点。图中每个转弯必须有可追溯的端口证据。

在生成计划时固定划分：48个相邻有向簇对用于校准；其余192个分为128个发现配置和64个验证配置。64个验证配置包含48个转弯簇对和16个非相邻直线簇对，并覆盖远近、正反方向。映射和连接图的拟合、候选规则选择均不得读取这64个配置的计数结果，预测冻结后再揭示。若验证发现新连接，记录本轮验证失败，更新图后另选独立确认实验，不能把更新后的拟合称为原验证成功。

另在已校准连接图条件下做留出某个源簇或目标簇的全部多跳路由验证，说明已知的相邻连接信息，避免把校准使用过的信息称为完全未知的源簇。

评价包括：预测的端口使用集合、方向/通道、转弯位置是否正确，以及计数是否在校准误差内。不能只比较延迟RMSE，或只证明某个模型比另一个略好。

若规则不统一，报告哪些源目标/操作/大小采用不同签名。重复签名稳定只说明本测试窗口中稳定，不能证明硬件在所有负载下始终如此。

### 9.2 块内成员替换

选择簇对0→1、0→4、5→6、5→9、0→15、3→12，每对源、目标都遍历A/B/C/D，形成16个成员组合，测64 B、4 KiB。

若仅更换块内CPE就改变端口签名，需要在模型中保留端点到端口的映射；不能继续假定“同一簇中的四个核完全等价”。若签名相同而性能改变，进一步检查端点LDM、发起循环、地址布局和仲裁。

所有成员组合保持缓冲容量、对齐、窗口、目标独立槽一致。代表配置再改变LDM偏移并复核；地址引起的性能差异与空间位置差异分别记录。

## 10. P5：用干扰验证已经观察到的资源共享

### 10.1 背景组合由实测路径选择

选择12条探针，覆盖四个方向象限、内部/边界、长/短距离。根据P3的实测签名为每条探针尽量选择三类背景：

1. 使用相同已观测有向端口的背景。
2. 经过相同内部部件、但使用不同已观测端口的背景。
3. 与探针的已观测内部资源分开的背景。

背景与探针首先使用不同端点簇；共享端点簇的实验单列。若某类配置在已观测图中不存在，应明确缺项，不能用几何标签冒充。

### 10.2 控制真实负载

先测所比较背景核对的单流可持续速率。以它们共同可达到的最低上限为参考，设置约30%、60%、85%三个目标注入速率，通过发送间隔控制；记录实际成功注入速率、完成速率、请求数和等待时间。

同一比较组使用相同目标B/cycle，不使用“各自峰值的相同比例”冒充绝对负载相同。实际速率偏离目标超过5%则标记未匹配，降低公共目标后重测；不能仅在分析中按实测速率相除就消除这一混合。

背景先启动、探针后计时、结束后停止背景。主对照采用同一探针内核的无背景/有背景ABBA或BAAB，组顺序随机。每项2048次RTT起步；性能内核批次计时、计时外校验，必要等待与内存顺序仍保留，主核/调度器负责超时兜底。

初筛探针请求1 KiB、回信8 B。选强/弱/异常配置后追加(请求,回信)=(8,8)、(4096,8)、(8,4096)、(4096,4096) B，以及探针反向。这些仍是往返协议，不按RTT/2报告纯单向链路延迟。

对代表配置，保持目标平均速率，比较W=1与W=4及不同启动相位；可使用发送端本地延迟0、1/4、1/2个背景批周期作为相位扰动，它不代表跨核精确同步相位。检查旧35%/3.5%差别是否依赖发包节奏。

### 10.3 联合计数的解释边界

分别采集空控制、仅探针、仅背景、探针加背景，并保留实际操作数和采集时长。

并发时的端口计数是多条流的合计。若无按流过滤能力，不能简单减去背景单独运行的计数，便声称剩下的是探针路径，因为并发可能同时改变两条流的速率和路径。

可以检验“两个单流固定路径的组合”是否解释总计数和阻塞位置；若解释失败，先检查负载、端点和通道因素，再考虑路径随负载变化。要确认哪条流改道，需流过滤/trace或进一步可辨识的实验，不能仅凭RTT下降宣称自适应路由。

## 11. P6：重复性、数据与最终验收

### 11.1 重复安排

- 能力与计数校准：先同一节点3个作业，发现错误立即修复，不进入批量扫描。
- 结构发现：一个节点完成P2–P4，按计数噪声和签名稳定性决定重复数。
- 独立确认：冻结映射、候选规则及质控参数，至少两个节点分别5个独立作业复核留出配置；节点分别汇总，再比较。
- 资源记录必须说明CG/芯片是否独占。q_share名称和1 MPE/64 CPE申请本身都不证明独占；计数器若包含其他作业流量且无法过滤，不给出确定路径结论。

### 11.2 原始输出

| 文件 | 必须包含 |
|---|---|
| capabilities.json | 版本、库哈希、权限、计数数组长度、计数位宽、作用域、资源独占状态 |
| core_cluster_counter_map.csv | 运行时全部编号、几何编号、PMU下标、映射证据 |
| counter_events.csv | 原始函数名、计数器冲突组、单位、范围、校准状态 |
| cases.csv | job/node/CG、源目标、操作、消息、N/W、目标负载、种子、event_pass |
| counters_raw.csv | before/after原值、原始差值、所有数组项、溢出检查；不只保存非零项 |
| counter_calibration.csv | 空控制、N缩放斜率、残差、事件方向/单位判定 |
| port_usage.csv | 每个源目标对的端口/通道使用签名、误差、证据case_id |
| topology_edges.csv | 两端部件及端口、观测方向、文档支持、实测支持、歧义标记 |
| route_candidates.json | 唯一或多候选通路、未解释事件、验证状态 |
| contention.csv | 成对RTT差、实际负载、相位、端点、阻塞事件与基线漂移 |
| validation.csv | 实际收发数、最终数据校验、超时、错误、采集完整性 |

性能路径中不逐消息全字节验证；正确性诊断另行逐消息验证，正式运行至少核对计数和最终每个有效槽。分别报告这两种验证覆盖范围。

### 11.3 结论分级

| 等级 | 可写的结论 | 必须满足 |
|---|---|---|
| A | 观测到的RMA逻辑连接与唯一可见路径 | 事件/编号已校准，端口关联和流量约束唯一，留出组合及独立作业复核通过 |
| B | 数据支持某类路由，仍有等价解释 | 有稳定硬件签名或干扰预测，但计数/路径分解不唯一 |
| C | 仅确认性能层次和争用关系 | 无空间计数能力，或候选模型仍不能预测新配置 |

所有图逐边区分“文档所述”“计数观测”“根据模型推断”“尚不确定”。不得把A等级的可见逻辑图扩写为所有内部线路、虚拟通道或仲裁器的完整物理图。

## 12. 无法使用空间计数器时的备选

若SDK不兼容、权限不可得、事件不覆盖RMA或只能提供总量，先争取平台提供对应的计数器/维护接口文档；不猜测寄存器地址，不直接写未知控制寄存器。

黑盒实验采用：

1. 同一新轻量内核测64×63核对的RTT及单流吞吐，复核2×2层次和编号；不依赖未验证的跨核时钟同步。
2. 针对旧强/弱背景，做块内成员替换、匹配注入速率、窗口/相位对照。
3. 扩大探针的源目标位置，扫描48种几何相邻有向背景，并追加能区分候选假设的跨行跨列背景。
4. 保留具体位置和端点特征，分别比较不同连接图与路由假设；先检查不同假设在可观测量上是否真的不同，再选测试。
5. 用全新源目标组合验证，并保留无法区分的等价模型。

这条备选能形成争用图和候选路由证据，但不能预先保证唯一识别物理拓扑。

## 13. 测试规模与执行顺序

下表是逻辑条件数量，不包含event_pass、重复作业、空控制、ABBA重复、校准及失败重测。令P为实际互斥事件所需的采集遍数。

| 批次 | 逻辑条件数 | 说明 |
|---|---:|---|
| 首次RMA事件试验 | 8核对×2大小×3次数=48 | 每事件遍；另做空/纯计算/DMA控制 |
| 64核PMU映射 | 64发送核×2次数=128 | 先采描述符事件，再用收发事件复核 |
| 240簇对PUT扫描 | 240×2大小×3次数=1440 | 48相邻方向是其中子集，不能再重复相加 |
| 块内成员替换 | 6簇对×16成员组合×2大小=192 | N固定为校准后选定值 |
| PUT/GET角色对照 | 8簇对×2大小×2操作=32 | 完整6大小扫描为后续针对性扩展 |
| 初始争用复核 | 12探针×3背景类型×3负载=108组 | 每组4次ABBA/BAAB，即432次探针运行 |

先完成48条件的事件试验，实测每次运行、每个计数遍和启动/回收耗时，计算后续预算：

`预计时间 = 各阶段实际运行次数 × 实测每次耗时 + 初始化/采集/排队时间`

不根据循环cycles直接估算整批作业墙钟时间，不一次提交所有阶段。P0/P1未通过时，扩大干扰扫描不是主线。
