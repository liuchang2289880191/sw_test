1.1 作业级性能监测与分析工具


    作业级性能监测与分析工具是基于性能工具接口和系统软件接口研制的一款系统级的
性能监测与分析工具，已内置在系统环境中，用户无需安装，只需要在程序的任务作业提交
时加上一个开启的系统参数选项即可。当前支持的选项包括使用步骤如下所示：


       作业提交时添加参数-perf


    例如：bsub -I -q q_debug -cgsp 64 -perf ./hostslave
    注意：作业提交时 –perf 必须添加在可执行程序前面,当前支持的参数如下，可根据
需要进行使用，目前支持的选项包括：
    a) –perf:使用默认配置文件进行性能监测
    b) –preff perf_file:使用自定义配置文件进行性能监测
    c) –perf_float:使用自定义的浮点默认配置文件进行性能监测
    它们是互斥选项，即在程序的一次提交中只能设置其中一个选项。

1.6 优化实例和常见的优化方法


      深度学习应用课题


   利用性能工具 API 监测其主核程序某核心段 Dcache Miss rate 为 52.6%。
   根据主核的 Cache 大小，采用合适的循环分块将 Dcache Miss rate 降低为 15.1%。
   核心段开销由 60s 降低为 2 秒，性能接近 Intel 核心。
   内存循环访问的数据量以 Cache 大小的 1/4~1/2 效果最佳。


      CESM 应用课题


   利用性能工具 API 监测其从核程序段
            – gld 单位时间内次数过高；
            – L1Cache Miss 频率过高。
   进一步利用 API 监测各个函数的 gld 次数
            – 从核数学函数库带来意外的 gld，将从核数学函数访问的查表数组 ldm 优化；

  迭代后，程序整体性能提升 15%。


 其他常见的优化方法


算法设计层面的数据局部性挖掘
    1) 计算核心段的数据尽量布局在 ldm 中；
    2) 同时提高 ldm 空间中数据的计算重用度，利用片内通信复用分布同行同列
        从核上的数据；
    3) 设计从核间协同并行的算法，进一步提高数据工作集的重用度。
程序设计层面的数据局部性挖掘
    1) 针对具有空间局部性的数据访问，利用好 DMA；
    2) 对 ldm 数据进行空间压缩，使用 int 类型足够的就不使用 long 类型；
    3) 针对分散多次访问的数据，设计结构体，使用 DMA 进行加速；
    4) 利用 SIMD 减少离散访问主存的次数。
程序设计层面的从核指令 Cache 局部性挖掘
    1) 提高程序中转移预测成功率
     • 将 if{} else{}结构中常走的路径放在 if(true){}中
    2) 减少从核指令 Cache 不命中的方法；
     • 压缩从核程序核心段指令大小<L1Cache_Size；
     • 实在压缩不了，按照核心段从核函数调用关系顺序链接各个*.o 文件。
