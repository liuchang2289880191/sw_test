           第一章 神威众核结构概述
  神威众核芯片采用主从异构结构，由通用计算主核和精简的计算从核组成，
具有超高的定点和浮点峰值性能和高的实际应用性能。

1.1 芯片结构
    神威众核芯片集成 6 个核组，每个核组包括 1 个主核和 1 个从核阵列，
 1 个从核阵列包含 64 个从核；片上集成 2 个系统接口，上述主要部件通过环
 形网络连接； 神威众核芯片的总体结构如下图 1-1 所示：

1.2 从核阵列结构
   神威众核芯片的从核以 8×8 阵列方式排布的从核阵列为基本单位进行管理，
从核之间以及从核与外部的交互通过阵列内网络进行互连。从核之间的网络采用
CMesh 网络，四个临近从核共享一个从核簇管理部件，并集成一个路由器。神威

1.3 从核结构

  神威众核处理器的从核使用一个 64×64 位的统一结构寄存器（SIMD 扩展
结构使用高 32 个条目、512 位宽的向量寄存器），由整数执行部件和浮点执行
部件共享，具体认作定点整数格式还是浮点数格式由程序员自行决定，所有运算
均在寄存器之间进行。
  支持字节（8 位）、半字（16 位）、字（32 位）和长字（64 位）的整数；
支持 IEEE754 标准的半精度（16 位）、单精度（32 位）和双精度（64 位）浮点
数据类型。
  支持短向量数据，包括长度为 16 的字（16×32 位）向量整数、长度为 32 的
半精度（32×16 位）向量浮点数据和长度为 8 的单精度（8×32 位）或双精度（8
×64 位）向量浮点数据。
   将 32 个 64 位的统一类型寄存器（$32-$63）扩展成为 32 个 512 位的向量寄
存器，每个寄存器的低 64 位仍然是基本结构的统一类型寄存器，存放 8 位、16
位、32 位和 64 位的整数，以及半精度、单精度或双精度浮点数据，而整个 512
位的寄存器则可以存放 512 位的整数向量或浮点向量。从核寄存器结构如图 1-3
所示：

   关于 SIMD 扩展和半精度支持详见《基础编译器 SIMD 用户编程手册》。
   神威众核处理器的每个从核具有一块高速的本地局部数据存储空间 LDM，
LDM 总容量为 256KB，该空间可配置成完全由软件管理，也可部分容量配置成
硬件自动管理的数据 Cache，两种管理方式的容量配比分档可调。
   配置成软件管理的局部存储时，从核可以使用访问 LDM 空间的 ld/st 的方
式加以访问，也可以使用发起异步 DMA 或 RMA 的方式实现 LDM 与外界的数
据批量交换；
   配置 Cache 时，LDM 支持 0KB、32KB 和 128KB 三档数据 Cache 容量配
置，通过提交作业时 bsub 选项-cache_size 0/32/128 进行配置。cache_size 默认为
0。

              第二章 编程模型
 2.1 众核程序结构
  一个神威众核程序通常由三部分组成：
  1、主函数
  进行众核加速前的主程序，运行在纯主核上，调用神威主核函数进行众核加
速；
  2、神威主核函数
  声明从核函数，设置从核函数参数，将从核函数 spawn 到从核阵列上并开始
从核阵列计算。从核阵列计算开始后，主核函数等待所有从核完成计算并退出，
在主核函数启动从核阵列后等待从核计算完成期间，主核函数可以执行与从核阵
列异步执行运行的在主核运行的代码。
  3、神威从核函数
  由主核函数 spawn 到从核上由从核异步执行的函数。

 2.2 从核函数
  从核执行单独编写的从核函数，主核将同一个从核函数 spawn 到从核阵列上
的每个从核，由从核进行计算，从核支持 C 和 Fortran，从核支持简单的 C++。
一个从核函数在主核的声明如下：
  ...
  extern SLAVE_FUN(MatrixMulSW)(void*);
  ...
  主核函数 spawn 从核函数时可以将一个主存地址以参数的方式传递给从核
函数，当需要向从核函数传递多个参数时，可以将多个参数声明为一个结构体，
在主核函数中创建结构体变量并对结构体赋值，spawn 时将结构体变量的地址以
参数的方式传给从核函数，从而实现向从核函数传递多个参数：
  ...
  typedef struct{
      int hA;
      int wA;
      float *eA;
  } Para;
  ...
  para.hA = M;
  para.wA = N;
  para.eA = &A[0];
  athread_spawn(func_slave, &para);
  ...
 以上程序通过数据结构 Para 将变量 M，N 和&A[0]传入从核函数。

2.3 从核组织方式
     每个从核簇由四个从核组成。从核为精简的 64 位 RISC 核心，支持 512 位
整数和浮点 SIMD 操作。四个从核共享一个从核簇管理部件，主要负责阵列内网
络的数据交互和流量控制，同时集成了用于批量访存的 DMA 引擎和从核批量数
据交互的 RMA 引擎。从核簇管理部件还负责从核及簇管理部件自身的异常、错
误、故障的报出，支持主核和维护对阵列内 IOR 的访问。其组织结构如图 1-2 所
示。

  CRTS_rid     从核所在行号（硬件编号，0-7）

2.4 存储层次

2.4.1 主存层次

  神威众核芯片一个核组内的存储分为位于主核的主存和每个从核私有的位
于每个从核的 LDM。编程时，从核函数栈空间默认位于主存中，在运行时加-b
选项可以将栈空间设置到 LDM 内。

                          第三章 编程接口
 3.1 编译与运行
     神威众核程序由 3 部分组成：
     1、运行于主核的主程序，通常为未使用众核加速的纯主核程序。
     2、主核程序，包括从核函数声明、从核函数参数设置、从核函数的 spawn 与
join 和位于从核函数 spawn 之后、从核函数 join 之前的与从核函数异步执行的由
主核运行的程序。
     3、从核程序，包括 LDM 变量声明和从核函数实现。
     神威众核程序的编译流程为：
    1、编译主程序 main.c
     sw9gcc -mftz -mieee main.c -o main.o
    2、编译主核程序 master.c
     sw9gcc -mftz -mieee master.c -o master.o
    3、编译从核程序 slave.c
     sw9gcc -mslave -mieee -msimd slave.c -o slave.o
    4、链接生成可执行程序 exe
     sw9gcc -mhybrid -static main.o master.o slave.o -o exe
     详细编译选项说明参见《基础编译系统用户手册》。
     众核程序需要使用 bsub 命令提交到计算节点运行，提交命令为：
    bsub -b -I -o out.log -q 队列名 -shared -n 1 -cgsp 64 -share_size 14000 ./exe


    编写和运行神威众核程序主要分为 4 个步骤：
    1、使用 ahtread 线程库单独编写主核程序和从核程序；
    2、用不同编译选项分别编译生成主核程序和从核程序的.o 文件；
    3、使用混合链接选项链接生可执行程序；
    4、将生成的可执行程序提交到计算结点进行计算
    主核程序运行在主核上，可以包含多个从核函数，一个主核程序如下所示：
1    #include <crts.h>
2
3     extern SLAVE_FUN(func_slave)(void*);
4
5     void master(void *para){
6       athread_spawn(func_slave,para);
7       athread_join();
8     }
    其中：
    第 1 行：引用公共运行时（CRTS）库头文件；

                                          5
  第 3 行：声明外部从核函数，从核函数通常在从核程序文件中声明和定义；
  第 6 行：将从核函数 func_slave 加载到从核阵列上进行计算，函数 func_slave
的参数由 para 提供。
  第 7 行：显式阻塞等待从核阵列完成计算；
  在第 6 行（从核启动）和第 7 行（从核执行结束）之间可以添加主核代码，
其代码在主核上与从核代码异步执行。

3.2.1 资源查询命令

  资源查询命令为：
  qload -w
  输入命令后显示如下信息：



  其中，
  QUEUE_NAME：队列名；
  CONFIG：队列中配置的 CPU 总数；
  IDLE：队列中空闲的 CPU 个数；
  IDLEMPE：队列中空闲的主核个数，一个主核运行一个进程，此数即为可以

    注意：
    一个 CPU 中通常包含 6 个核组（1 个核组为 1 个主核+64 个从核），因此
IDLE 和 IDLEMPE 通常为 6 倍关系。


3.2.2 常用作业提交选项

  常用作业提交命令为：
  bsub -b -I -o out.log -q 队列名 -shared -n 1 -cgsp 64 -share_size 15000 ./exe
  其中，
  -b：将从核栈空间放在 LDM 内。从核栈空间（在从核函数中声明的变量、
从核文件中的函数等）默认位于该从核在主存内的从核私有段（详见 2.4 节），
若不加-b 选项，则从核对从核栈变量的访问为从核访主存，加-b 选项后从核栈空
间位于 LDM 内，则从核对从核栈变量的访问为本地 LDM 访问。
  -I：交互式作业提交，不加-I 时为后台提交。当队列中空闲计算资源不足时
可以通过后台提交作业方式将作业 PEND 到队列尾端，一旦队列中有足够的空
闲资源时 PEND 的作业会自动提交运行。


                                       6
  -o：将作业输出保存到指定的文件中。
  -q：指定作业提交的队列。
  -shared：以非独占方式提交作业。一个 CPU 内有 6 个主核，一个主核运行
一个进程，因此，一个 CPU 应当可以运行 6 个串行作业，但若用独占方式提交
作业，即在提交作业时不加-shared 选项时，即使作业仅使用 1 个主核（1 个进
程），其它作业也无法提交到它运行的 CPU 上，它运行的 CPU 上其它 5 个主核
处于空闲状态且无法运行任何作业直到 CPU 完全空闲。添加-shared 选项以非独
占方式提交作业，当一个作业占用一个 CPU 内的 1 个主核时，依然可以该 CPU
的其它主核提交作业。
  -n：指定作业进程数。
  -np：每个 CPU 内运行的进程数。
  -cgsp：每个核组启动的从核数，只有添加此选项后主存内作为从核私有段的
部分内存才可使用，因此即使作业不使用从核计算依然需要添加此选项。
  -share_size：指定作业使用的主存大小，以 MB 为单位。一个核组内存大小
为 16GB，share_size 大小通常不超过 15000。作业使用的内存空间大小由此参数
指定，无法动态查看作业运行时 CPU 内存使用情况。
    -host_stack：指定作业使用的主核栈空间，主核栈空间不应超过 share_size 指
定的大小。

2
3   #define BLOCK_SIZE 16

6   #define WB 5*BLOCK_SIZE
7
8   typedef struct {
9     int width;
10    int height;
11    int stride;
12    double* elements;
13 } Matrix;
14
15 extern void MatMul(Matrix *A, Matrix *B, Matrix *C);
16
17 int main(int argc, char* argv[]){
18    Matrix A, B, C;
19    int size_A, size_B, size_C;
20    int i, j;
21
22    CRTS_init();
23
24    A.width = WA;
25    A.height = HA;

 4.1 从核数据 Cache
    如 2.4.2 节所述，可以将从核 LDM 的一部分空间配置为从核 Cache，配置
Cache 时，LDM 支持 0KB、32KB 和 128KB 三档数据 Cache。从核数据 Cache 支
持硬件淘汰和装填，一致性的相关说明如下：
   1、 从核 Cache 不保证与主核 Cache 的一致性。主核访存过程中无法从从核
Cache 中获得最新数据；但从核淘汰或装填时，能够获取主核 Cache 中的最新数
据；
   2、 从核 Cache 不保证与从核 Cache 的一致性。从核访存过程中，始终无法
从其他从核的 Cache 中获得最新数据；
   3、 从核 Cache 不保证与软件管理的 LDM 空间的一致性。从核 DMA 过程
中，无法获得从核数据 Cache 中的最新数据；
   4、 为避免由于从核 Cache 不保证一致性带来的假共享问题，从核 Cache 对
共享主存空间（从核主存虚空间中的共享段）的写回支持带屏蔽的细粒度写机制，
屏蔽粒度为 4B，一个 Cache 行中只有确实被修改过的数据才会写入主存（Dcache
写主存过程中，如果存在写数据带部分屏蔽，存控对相应的 128B 或 64B 采用读
改写方式处理）；
   5、 对于“从核 Cache-从核 Cache”、“从核 Cache-DMA 操作访问”、“从
核 Cache-同一片主存空间的不可 Cache 访问”或“从核 Cache-主核 Cache”之间
存在真共享数据且最新副本在从核/主核 Cache 中，或“从核 Cache-从核 Cache”
之间存在独占 Cache 行所有权限转移时，软件必须显式对数据所有者从核/主核
的 Cache 进行刷新，通过 Memb 保证刷新完成，最后双方通过硬件同步或主存空
间上的原子操作进行同步。

 4.1.1 使用方法
    通过提交命令（bsub）的-cache_size 选项进行配置和使用，设置从核数据
Cache 后，从 LDM 的尾部开辟一块指定大小的空间作为从核数据 Cache，如下：
    -cache_size 0/32/128，单位为 KB，其中：
    -cache_size 0：从核数据 Cache 大小为 0KB，即不使用从核数据 Cache；
    -cache_size 32：从核数据 Cache 大小为 32KB；
    -cache_size 128：从核数据 Cache 大小为 128KB。

4.3.2 使用方法

1、在从核函数内声明 LDM 共享变量

    在 LDM 变量前添加__thread_local_share 修饰符将变量声明为 LDM 共享变
量，如下：
__thread_local_share double A_s[WA*HA] __attribute__ ((aligned(64)));
__thread_local_share double B_s[WB*WA] __attribute__ ((aligned(64)));


2、通过 DMA 方式将数据从主存加载到共享 LDM 空间内

  函数接口：
  int CRTS_memcpy_sldm (void *dst, void *src, int len, int direction);
  函数说明：
  从核发起共享 ldm 空间的 DMA 数据传输，需要 LDM 共享空间内的所有从
核调用。
  参数说明：
  dst：目标地址（4B 对界/对齐）；
  src：源地址（4B 对界/对齐）；
  len：数据传输量（4B 整数倍）；
  direction：数据传输的方向，可选项有 MEM_TO_LDM 和 LDM_TO_MEM。
  返回值：
  成功：0；
  失败：非 0。

 4.4 手工 SIMD 优化
  灵活使用从核内的向量寄存器是提升从核计算性能的重要方法，神威从核提
供了丰富的手工 SIMD 优化接口，完整的接口说明见《基础编译器 SIMD 用户编

4.4.1 算法描述与接口

      从核矩阵转置主要通过向量混洗接口实现，接口如下：
      函数名：
         simd_vshfw—— 字向量全混洗
      参数说明：
         intv8 va;
         intv8 vb;

                                            34
          double fc;
    返回值
           intv8 vd
    功能说明
    操作数寄存器为 Va、Vb、Fc 和 Vd。Vd 的八个 32bit 的数由 Va 和 Vb 装
填，具体如何装填由 Fc 说明：
           Fc 的<31:28>指出 vd 的<255:224>来自 Va 或 Vb 的位置
           Fc 的<27:24>指出 vd 的<223:192>来自 Va 或 Vb 的位置
           Fc 的<23:20>指出 vd 的<191:160>来自 Va 或 Vb 的位置
           Fc 的<19:16>指出 vd 的<159:128>来自 Va 或 Vb 的位置
           Fc 的<15:12>指出 vd 的<127:96>来自 Va 或 Vb 的位置
           Fc 的<11:8>指出 vd 的<95:64>来自 Va 或 Vb 的位置
           Fc 的<7:4>指出 vd 的<63:32>来自 Va 或 Vb 的位置
           Fc 的<3:0>指出 vd 的<31:0>来自 Va 或 Vb 的位置
    Fc 相应的 4bit 位置的最高位为“0”时，Vd 相应的数来自 Va；为“1”时，
Vd 相应的数来自 Vb。Va/Vb 分成自然对界的 8 个 32bit，Fc 相应的 4bit 位置的
低 3bit（0~7）用于指示是第几个 32bit 数据，为“0”表示第 0 个 32bit（[31:0]），
依次类推。
