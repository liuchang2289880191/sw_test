# RMA 硬件计数器验证程序

这是独立的新补充程序，不修改之前的 RMA 实验。当前阶段只验证 SDK 接口、读数数组和 RMA 响应，不输出拓扑或 XY/YX 判定。

## 首次运行

解压后进入 rma_pmu_probe，运行：

```bash
bash run_pmu_probe.sh q_share
```

脚本在找不到 swgcc 时加载 `swgcc/1473`，使用之前成功的主从核编译参数和资源请求。登录节点只编译，目标程序通过 bsub 在计算节点执行。`swperf.h` 和库来自 `/usr/sw/penv`。头文件中有声明不代表链接和运行权限已经验证；编译或链接失败时保留 build.log，不替换为 x86 库。

默认 smoke：7 个事件（RMA PUT 描述符、RMA PUT 传输量、L/S/N/W/E 五个 req_p1up_flit），核对 0→1 与 1→2；64 B；N=0、64、256；PUT 和纯本地操作两种模式；各重复 2 次。共 **168 个内核调用，一个作业**。这两种核对只用于先验证同块/跨块事件响应。

`PMU_CASE` 后面的 `PMU_STAGE init_count` 覆盖初始化、读数、内核运行、最终读数阶段。每例 60 秒主核看门狗，从核 reply 等待也有超时。出现 PMU_RETURN 表示该例已返回。内核错误、数组写入异常、计数下降时停止，不将它们当作有效结果。

也可以只编译：`PMU_BUILD_ONLY=1 bash run_pmu_probe.sh q_share`。

## 读数可用后的扩展标定

检查 smoke 结果后，再执行：

```bash
PMU_PROFILE=calibrate bash run_pmu_probe.sh q_share
```

22 个事件：原来的 7 个，加五个方向各自的 req_p1down、res_p1up、res_p1down；8 个核对 0→1、1→2、0→8、8→16、18→20、18→34、0→54、54→0；64 B/4096 B；N=0、256、1024、4096；两种模式，各重复 3 次，共 **8448 个内核调用**。事件逐个配置、逐次运行，不同时配置冲突事件。扩展仍是标定，未实施完整拓扑扫描、GET、DMA-only、100 次空白窗口或跨节点确认。

## 测量口径

- 每条流 W=1，单向 PUT，每次等待本地完成；接收方等待全部 N 次远端完成后，各核才进行输出 DMA。没有每条消息的应用层回包，硬件完成通知仍然存在。
- 源数据固定，每次传输相同内容；末尾逐字节校验最终缓冲，并核对完成计数。不能声称检查了每次中间传输内容。
- 主核 init 后读 before，spawn/join 后读 after，保存两个原始值。区间内不打印进度；没有使用自动 wrap/profile 编译选项。
- 区间覆盖整个内核：配置 DMA、固定初始化、同步、数据传输、最终校验及结果 DMA。N=0 提供启动基线。脚本按 N 拟合截距和斜率，不把整个 delta 都当成 RMA。
- local 模式在源核执行 N 次 volatile 本地缓冲复制。它用于筛查随循环增加的非 RMA 活动，执行时间/指令数不与 PUT 精确匹配。默认栈位置没有改变，记录缓冲和栈变量地址供检查，仍需结合 SDK/反汇编确认。
- 文档描述 CG 事件返回 16 个 unsigned long；程序留出额外哨兵，检测常见的未写入或越界情况。CSV 用 cell=0..15，**尚不当作几何块编号**。
- 不假设计数器位宽。after < before 直接标记失败，避免错误地按 64 位计算回绕差值。对未发生明显下降的多次回绕，也需通过进一步位宽标定排除。
- q_share 的一核组请求不证明计数器独占；所有其他进程和核组的影响仍需标定。可用 PMU_RESOURCE_NOTE 记录分配情况。
- 两次/三次重复来自同一作业，不是独立作业。事件串行采集不是同时发生的逐包轨迹。即使读数随 N 增长，也不能直接判定完整路由。

## 结果

- `build.log`、`build_info.txt`、`swperf.h`：编译与 SDK 记录。
- `job.log`、`runtime.txt`：进度、计算节点和运行规模。
- `counters.csv`：每个事件每次运行的 16 个原始计数单元。
- `checks.csv`：64 核的完成、最终缓冲校验、地址、循环耗时。
- `count_scaling.csv`：每个事件/模式/核对/大小/cell 的 N 斜率、截距、拟合 RMSE 和重复极差；均为描述统计。
- `audit.json`：数据结构和完成计数检查。integrity passed 不等于硬件事件语义验证通过。

首轮请保留并回传整个 results_pmu_* 目录。先看 TBOX 是否响应，再看端口计数是否随 N 变化。默认仅测 req_p1up，零增量不表示没有路径；需要扩展事件、DMA 对照、映射和隔离检查后再下结论。

本包本地检查覆盖 C 接口替身语法检查、脚本语法和分析器模拟数据检查；尚未使用目标 swgcc 编译或在 SW39000 执行。
